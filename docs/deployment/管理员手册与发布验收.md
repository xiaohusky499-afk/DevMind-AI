# DevMind AI 管理员手册与发布验收

## 1. 发布物

- `Dockerfile`：FastAPI 与文档 Worker 共用的 Python 3.12 非 root 镜像。
- `front/Dockerfile`、`front/nginx.conf`：前端静态镜像、SPA 回退、HTTP/WebSocket API 反向代理。
- `docker/docker-compose.yml`：本地开发基础设施。
- `docker/docker-compose.production.yml`：生产密钥、应用服务、只读文件系统、日志轮转和端口收敛。
- `scripts/migrate.py`：带版本和 SHA-256 账本的数据库迁移工具。
- `scripts/release.py`：生产校验、初始化、升级和应用镜像回滚入口。
- `scripts/backup.py`：升级前备份、校验与隔离恢复演练。

## 2. 首次部署

1. 复制环境模板：

   ```powershell
   Copy-Item docker/production.env.example docker/production.env
   New-Item -ItemType Directory docker/secrets
   ```

2. 修改 `docker/production.env` 的域名、镜像标签和资源名称。
3. 在 `docker/secrets/` 创建以下无扩展名文件，每个文件只保存一个值：

   - `postgres_password`：至少 12 字符；
   - `redis_password`：至少 16 字符；
   - `minio_access_key`：不得使用 `minioadmin`；
   - `minio_secret_key`：至少 16 字符；
   - `jwt_secret`：至少 32 字节；
   - `dashscope_api_key`：有效的模型服务凭证；
   - `metrics_token`：至少 24 字节。

4. 确认 `internal_kb_qa/models/bge-m3` 和 `internal_kb_qa/models/bge-reranker-v2-m3` 已准备完成。
5. 校验并初始化：

   ```powershell
   uv run python scripts/release.py validate
   uv run python scripts/release.py init
   ```

6. 访问 `http://服务器地址:8080/`，并检查后端容器健康状态。

生产环境只公开 Web 端口。PostgreSQL、Redis、MinIO API 和 Milvus 仅绑定 `127.0.0.1`，供本机备份与维护；ClamAV、etcd、MinIO Console、Neo4j 不公开。

## 3. 升级

使用不可变版本标签，不要使用同一个标签覆盖旧镜像：

```powershell
uv run python scripts/release.py upgrade `
  --backend-image registry.example.com/devmind/backend:2026.08.29 `
  --web-image registry.example.com/devmind/web:2026.08.29
```

升级顺序固定为：配置与密钥校验 → PostgreSQL/MinIO/Milvus 统一备份 → 构建或拉取镜像 → 执行待处理迁移 → 更新 Backend、Worker、Web → 等待健康检查。任何步骤失败都会停止后续步骤。

数据库迁移状态：

```powershell
uv run python scripts/migrate.py status `
  --env-file docker/production.env `
  --compose-file docker/docker-compose.yml `
  --compose-file docker/docker-compose.production.yml
```

已执行迁移的文件内容不得修改；Checksum 不一致时工具会拒绝继续，必须新增更高编号迁移。

## 4. 回滚

回滚只切回上一版本应用镜像，不自动逆向数据库结构：

```powershell
uv run python scripts/release.py rollback `
  --backend-image registry.example.com/devmind/backend:2026.08.28 `
  --web-image registry.example.com/devmind/web:2026.08.28
```

因此每个数据库迁移必须至少向前兼容一个应用版本：先新增字段或表，应用完成切换并稳定后，再在后续版本删除旧结构。确需恢复数据时，按照 [备份与恢复](备份与恢复.md) 先做隔离恢复，禁止直接覆盖现有库。

## 5. 日常检查

```powershell
docker compose --env-file docker/production.env `
  -f docker/docker-compose.yml `
  -f docker/docker-compose.production.yml ps

docker compose --env-file docker/production.env `
  -f docker/docker-compose.yml `
  -f docker/docker-compose.production.yml logs --since 30m backend worker
```

重点关注：容器健康状态、HTTP 5xx、P95 延迟、死信文档任务、Worker 租约过期、RAG 连续失败和备份校验结果。指标和告警配置见 [部署说明](部署说明.md)。

## 6. 故障处理

| 现象 | 检查 | 处理 |
|---|---|---|
| Backend 启动失败 | `backend` 日志中的生产配置校验 | 补齐密钥文件、关闭 Debug、启用 ClamAV，不要绕过校验 |
| 数据库迁移失败 | `schema_migrations` 与失败 SQL | 保持旧应用运行，修复为新编号迁移后重试 |
| Worker 无进度 | Worker 日志、任务租约、ClamAV/MinIO/Milvus 健康 | 恢复依赖后由租约和重试机制接管；死信任务人工重试 |
| 前端 502 | `backend` 健康状态与 Nginx 日志 | 先恢复 Backend，再重启 Web |
| RAG 无引用 | 文档状态、Milvus 行数、权限过滤与模型路径 | 重新索引对应文档，不直接修改向量库 |
| 发布后异常 | 新旧镜像日志和健康检查 | 执行应用镜像回滚；不要逆向执行 SQL |
| 备份校验失败 | manifest、磁盘空间、对象数量 | 隔离失败批次并重新备份 |

## 7. 发布验收用例

本阶段按要求不执行压力测试。每次发布至少完成：

1. `uv run pytest -q` 全量自动化测试；
2. `npm --prefix front run build` 前端生产构建；
3. `uv run python scripts/release.py validate` 生产配置与密钥校验；
4. 展示页 `/`、登录页 `/login`、工作台 `/workspace` 在 Chrome、Edge 最新稳定版检查；
5. 768–1024px 平板布局、低于 768px 移动布局检查；
6. 账号密码注册登录、短信登录、退出登录；
7. 创建知识库、上传测试文档、等待 Worker 完成索引；
8. 发起问题，检查流式回答、引用、可信度、历史记录和收藏；
9. 使用 viewer/editor/admin 账号检查越权拒绝；
10. 执行一次备份 `verify` 和带 `--cleanup` 的隔离恢复演练。

演示数据由 `tests/live_e2e.py` 创建并使用 `internal_kb_qa/data/rag_seed/tech.md`，仅用于非生产验收环境。执行前必须确认目标数据库不是生产库。

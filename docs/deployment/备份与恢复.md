# PostgreSQL、MinIO 与 Milvus 备份恢复

## 1. 备份范围

`scripts/backup.py` 在同一批次内生成三类数据快照：

- PostgreSQL 16：`pg_dump` 自定义格式，包含业务表、约束和索引。
- MinIO：导出 `devmind-documents` 全部对象，保留对象名、内容类型、大小和 SHA-256。
- Milvus：导出当前业务 Collection 的全部标量字段、稠密向量和稀疏向量；恢复时重建 Schema 与索引。

根目录 `manifest.json` 记录组件计数以及每个备份文件的大小和 SHA-256。任何文件缺失、新增或内容变化都会导致校验失败。备份目录已加入 Git 忽略，不能提交业务数据。

Milvus 使用逻辑快照是有意的：当前开发环境的 Milvus 2.4.4 存在仅含删除日志的历史 Segment，官方物理备份工具会拒绝该 Segment。逻辑快照只导出查询可见行，并同时记录 `source_reported_row_count`，便于审计存储统计与有效数据的差异。

## 2. 创建与校验

执行前应暂停 API 和 Worker 的写入流量，确保 PostgreSQL、MinIO 与 Milvus 处于同一业务时间点。读取可以继续。

```powershell
# 从项目根目录运行
$env:PYTHONPATH='.'

uv run python scripts/backup.py create --output backups
uv run python scripts/backup.py verify --input backups/devmind-YYYYMMDD-HHMMSS
```

只有 `create` 返回最终目录且 `verify` 成功时，备份才可进入保留库。`.partial-*` 是未完成批次，不得用于恢复。

## 3. 隔离恢复演练

```powershell
$env:PYTHONPATH='.'
uv run python scripts/backup.py restore-drill `
  --input backups/devmind-YYYYMMDD-HHMMSS `
  --cleanup
```

演练不会覆盖现有资源，而是创建随机命名的：

- PostgreSQL：`devmind_restore_<8位ID>`；
- MinIO：`devmind-restore-<8位ID>`；
- Milvus：`<原集合名>_restore_<8位ID>`。

工具验证 PostgreSQL 核心表计数、MinIO 对象数量及大小、Milvus 可查询行数。`--cleanup` 只允许删除上述隔离前缀资源；名称不符合规则时会拒绝操作。

生产恢复不得直接覆盖原库。先完成隔离恢复和业务抽查，再在维护窗口通过配置切换或受控导入完成切换；旧资源保留至验收结束。

## 4. 保留与异地副本

推荐保留策略：每日备份保留 14 天、每周备份保留 8 周、每月备份保留 12 个月。以下命令默认只列出候选项：

```powershell
uv run python scripts/backup.py prune --output backups --days 14
uv run python scripts/backup.py prune --output backups --days 14 --confirm
```

生产环境至少保留一份异机或对象存储副本，并启用版本控制或不可变保留。复制后必须在目标端重新运行 SHA-256 校验。建议目标为 RPO 24 小时、RTO 4 小时；正式数值需由部署方结合备份频率和数据规模确认。

## 5. 故障处置

- `verify` 失败：隔离该批次，不要恢复；重新生成备份并检查磁盘或传输链路。
- PostgreSQL 恢复失败：检查 PostgreSQL 版本、磁盘空间与扩展；目标库必须不存在。
- MinIO 恢复失败：检查 Bucket 是否已存在、凭证和剩余空间。
- Milvus 恢复失败：检查向量维度、Milvus 健康状态和索引构建日志；失败的隔离 Collection 可用带 `--cleanup` 的演练命令清理。
- 跨组件计数不一致：保持维护模式，检查文档任务是否仍在执行；重新备份，不能手工修改 manifest。

## 6. 当前验收记录

2026-08-28 已完成一次真实演练：PostgreSQL 1 个组织、6 个用户、6 个知识库、9 个文档、20 个文档片段；MinIO 9 个对象；Milvus 20 条查询可见向量。恢复校验通过，隔离数据库、Bucket 和 Collection 已清理。

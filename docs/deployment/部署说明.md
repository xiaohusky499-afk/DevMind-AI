## 密钥管理

后端支持两种注入方式：普通环境变量 `NAME`，或文件挂载 `NAME_FILE`。同一密钥不能同时配置两种方式，文件内容不能为空。生产环境推荐把 Secret 挂载到 `/run/secrets/`，再参照 `docker/production.env.example` 配置文件路径。

必须独立管理的密钥：

- `JWT_SECRET_FILE`：JWT 签名密钥，至少 32 字节，不得与任何数据库密码复用。
- `POSTGRES_PASSWORD_FILE`（或完整的 `DATABASE_URL_FILE`）：PostgreSQL 业务库凭证。
- `REDIS_PASSWORD_FILE`：Redis 凭证。
- `MINIO_ACCESS_KEY_FILE` 与 `MINIO_SECRET_KEY_FILE`：对象存储凭证。
- `DASHSCOPE_API_KEY_FILE`：模型服务凭证。

`docker/secrets/`、`.env`、`config.ini` 与 `config.local.ini` 已加入 Git 忽略。不要把真实密钥写入 Compose 文件、镜像或日志。复制 `.env.example` 并替换所有占位值后，再把同一组数据库与 MinIO 凭证填入 `config.local.ini`。开发 Compose 端口只绑定本机回环地址；生产部署须使用本目录的生产 Compose 文件与独立密钥文件。当 `APP_ENV` 不是 `development` 时，后端会拒绝默认或不安全配置并终止启动。

## 权限模型

所有知识内容同时经过三层校验：

1. 用户与资源必须属于同一组织，跨组织资源统一按不存在处理。
2. 用户必须是知识库成员；`viewer` 可查看，`editor` 可编辑文档，`admin` 可管理知识库和成员。
3. 文档/FAQ 密级不得高于用户密级；`team` 与 `confidential` 内容还要求部门一致，`public` 内容不限制部门。

RAG 检索先在 PostgreSQL 计算允许访问的文档 ID，再将该集合传入 Milvus 过滤。引用列表和引用详情会在读取时再次检查权限，成员、部门或密级变化后不会继续暴露旧引用内容。

阶段验收命令（不包含压力测试）：

```powershell
uv run pytest -q
$env:PYTHONPATH='.'
uv run python tests/live_permission_security.py
```

## 日志、指标和告警

FastAPI 与文档 Worker 统一输出单行 JSON 到标准输出，供 Docker 日志驱动、Loki 或 ELK 采集。公共字段包含 `timestamp`、`level`、`event`、`logger`、`message`；HTTP 请求附加 `request_id`、标准化路由、状态码和耗时，登录后日志上下文附加用户及组织 ID。密码、Token、API Key、手机号、邮箱和 IP 会在输出前脱敏，不记录请求正文与查询参数。

Prometheus 从 `GET /metrics` 采集以下指标：

- `devmind_http_requests_total`：按方法、标准化路由和状态码统计请求。
- `devmind_http_request_duration_seconds`：HTTP 耗时直方图。
- `devmind_http_requests_in_progress`：当前请求数。
- `devmind_document_tasks`、`devmind_document_stale_tasks`：持久化任务状态及过期租约。
- `devmind_rag_retrieval_runs_5m`、`devmind_rag_retrieval_latency_ms`：近 5 分钟检索量与延迟。
- `devmind_rag_failed_answers_15m`：近 15 分钟失败回答数。
- `devmind_metrics_collection_error`：PostgreSQL 业务指标采集是否失败。

开发环境未配置 `METRICS_TOKEN` 时可直接访问；生产环境必须通过 `METRICS_TOKEN_FILE` 注入至少 24 字节的独立凭证。Prometheus 使用 `Authorization: Bearer <token>`，人工检查也可使用 `X-Metrics-Token`。

Prometheus 抓取配置位于 `docker/monitoring/prometheus.yml`，规则位于 `docker/monitoring/alerts.yml`，覆盖后端不可用、5xx 比例、P95 延迟、死信任务、Worker 过期租约、RAG 连续失败和业务指标采集失败。`alertmanager.example.yml` 仅是接收器模板；正式部署前必须替换为企业内部告警 Webhook，不能使用示例地址。

配置校验：

```powershell
docker run --rm `
  -v "${PWD}/docker/monitoring:/etc/prometheus:ro" `
  -v "${PWD}/docker/monitoring/metrics_token.validation:/run/secrets/metrics_token:ro" `
  --entrypoint promtool `
  prom/prometheus:v3.5.0 `
  check config /etc/prometheus/prometheus.yml
```

`metrics_token.validation` 仅用于静态配置检查，不得作为生产凭证。

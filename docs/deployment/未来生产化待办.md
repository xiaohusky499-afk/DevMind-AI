# DevMind AI 未来生产化待办

## 当前范围决定

当前项目仅要求在本机运行和验收，不进行正式公网生产部署。因此下列事项作为未来生产化待办留存，不属于当前本机版本的交付阻塞项：

1. 正式短信供应商联调。
2. 企业 SSO / OIDC 联调。
3. 预发布环境备份恢复演练。
4. 生产域名、TLS 和外部密钥管理配置。

## 1. 正式短信联调

当前系统已经实现验证码生成、Redis 存储、过期、一次性校验，以及手机号/IP 发送和验证限流。本机开发模式可返回 `debug_code`。未来生产化时需要：

- 选择阿里云短信、腾讯云短信等供应商。
- 准备应用凭证、短信签名和审核通过的验证码模板 ID。
- 在短信服务适配器中调用供应商 API。
- 仅在供应商受理成功后返回“验证码已发送”。
- 生产环境禁止返回 `debug_code`，日志不得记录完整验证码。
- 验证验证码过期、重复使用、错误次数和发送频率限制。

## 2. 企业 SSO / OIDC 联调

优先使用 OIDC；仅在企业身份平台不支持 OIDC 时考虑 SAML。需要身份平台管理员提供：

- Issuer、Authorization Endpoint、Token Endpoint、JWKS URL。
- Client ID、Client Secret。
- Redirect URI、Logout Redirect URI。
- `openid profile email` Scope。
- 部门、职位、用户 ID 和用户组 Claim 映射。
- 测试用户和允许登录的企业用户组。

未来需要实现或完善：

```text
GET  /api/v1/auth/sso/config
GET  /api/v1/auth/sso/login
GET  /api/v1/auth/sso/callback
POST /api/v1/auth/sso/logout
```

验收时必须验证签名、Issuer、Audience、过期时间、State、Nonce、用户禁用、用户组限制及知识库 RBAC。

## 3. 预发布环境备份恢复演练

项目已提供 PostgreSQL、MinIO 和 Milvus 的统一备份、校验及隔离恢复工具。未来拥有独立预发布环境后执行：

```powershell
# 从项目根目录运行
$env:PYTHONPATH='.'

uv run python scripts/backup.py create --output backups
uv run python scripts/backup.py verify --input backups/devmind-YYYYMMDD-HHMMSS
uv run python scripts/backup.py restore-drill `
  --input backups/devmind-YYYYMMDD-HHMMSS `
  --cleanup
```

演练需要核对 PostgreSQL 核心表数量、MinIO 对象名称和大小、Milvus 可查询向量数量，以及文档、Chunk 和引用关系。恢复只能进入隔离资源，禁止直接覆盖业务库。

## 4. 生产域名、TLS 与密钥

未来生产部署需要准备正式域名、DNS 权限、TLS 证书或自动签发平台，以及服务器、负载均衡或 Ingress 权限。推荐链路：

```text
用户 → HTTPS 443 → 负载均衡 / Ingress / 边缘 Nginx
     → DevMind Web :8080 → Backend :15200
```

生产环境只公开 80/443，不直接公开 Backend、PostgreSQL、Redis、MinIO、Milvus、ClamAV 和 etcd 端口。

生产密钥目录应包含：

```text
docker/secrets/
├── postgres_password
├── redis_password
├── minio_access_key
├── minio_secret_key
├── jwt_secret
├── dashscope_api_key
└── metrics_token
```

密钥不得提交 Git，不得相互复用；正式环境建议迁移到 Vault、云 Secret Manager 或 Kubernetes Secret。生产配置通过以下命令校验：

```powershell
uv run python scripts/release.py validate --env-file docker/production.env
```

## 本机版本完成标准

本机版本满足以下条件即可视为本期完成：

- PostgreSQL、Redis、MinIO、Milvus 和 ClamAV 可通过 Docker 启动。
- Backend 使用最终端口 `15200` 并通过健康检查。
- Frontend 使用 `5173`，展示页、登录页和工作台路由独立可访问。
- 账号密码及开发验证码可以完成注册登录。
- 知识库、文档上传、Worker 入库、RAG 检索、重排、流式回答和引用链路可运行。
- 历史记录、收藏、个人资料、系统设置等本机功能可使用。
- 自动化测试、真实端到端脚本和前端生产构建通过。

正式短信、企业 SSO、预发布恢复以及生产域名/TLS 在决定部署生产环境时再启动开发和联调。

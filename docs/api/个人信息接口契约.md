# DevMind AI 个人信息接口契约

本文件定义个人信息编辑页的读取与保存接口。仅作为后端实现契约，不修改现有后端代码。

基础地址：`http://localhost:15200/api/v1`。所有请求使用 Access Token 获取当前用户，不允许客户端传入或修改 `user_id`。

## 接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/me/profile` | 读取个人档案与使用偏好 |
| PATCH | `/me/profile` | 保存个人档案与使用偏好 |

统一响应：

```json
{ "request_id": "req_xxx", "data": {}, "error": null }
```

## 保存个人信息

`PATCH /me/profile`

```json
{
  "display_name": "张工程师",
  "avatar_url": null,
  "gender": "male",
  "birth_date": "1998-08-12",
  "email": "zhang@example.com",
  "phone": "+8613800138000",
  "phone_verification_code": "123456",
  "department_name": "平台研发部",
  "job_title": "高级后端工程师",
  "employee_no": "DM-2024-018",
  "joined_at": "2024-03-18",
  "bio": "专注企业平台与知识系统研发。",
  "timezone": "Asia/Shanghai",
  "locale": "zh-CN"
}
```

成功时返回保存后的完整对象。前端以响应内容更新侧栏中的头像、姓名、职位与部门。

## 字段规则

| 字段 | 规则 |
| --- | --- |
| `display_name` | 1–64 个字符，必填 |
| `gender` | `male`、`female`、`unspecified` |
| `birth_date` | ISO 日期；不得晚于今天 |
| `email` | 合法邮箱；同组织唯一；变更后建议进入邮箱验证流程 |
| `phone` | E.164 格式；变更后必须通过短信验证码验证 |
| `phone_verification_code` | 仅变更手机号时提交；验证码通过 `/auth/send-code` 获取 |
| `department_name` | 1–128 个字符 |
| `job_title` | 1–128 个字符 |
| `employee_no` | 最多 64 个字符；同组织非空时唯一 |
| `joined_at` | ISO 日期；不得晚于今天 |
| `bio` | 最多 500 个字符 |
| `timezone` | 合法 IANA 时区 |
| `locale` | 如 `zh-CN`、`en-US` |

返回错误码：`PROFILE_NOT_FOUND`、`EMAIL_VERIFICATION_REQUIRED`、`PHONE_ALREADY_EXISTS`、`EMPLOYEE_NO_ALREADY_EXISTS`、`PHONE_VERIFICATION_REQUIRED`。

## 后端持久化要求

1. 基础档案写入 `user_profiles`，邮箱和手机号等账号字段写入 `users`；时区、语言在同一事务中写入 `user_preferences`。
2. 邮箱或手机号修改不得直接生效：先创建验证挑战，验证通过后才更新 `users`。
3. 写入成功后记录 `audit_logs`，动作名为 `user.profile.updated`，不要记录生日、手机号和简介原文。
4. 服务端返回 `editable_fields`；前端将未授权字段展示为只读，而不依赖硬编码。
5. `organization_id` 从 Access Token 对应的数据库用户解析，客户端不能提交；所有读取和更新同时匹配 `user_id + organization_id`。

## 当前实现状态

- `GET /me/profile` 和 `PATCH /me/profile` 已由 PostgreSQL 16 持久化实现。
- 姓名同步到 `users.nickname`，档案写入 `user_profiles`，时区与语言写入 `user_preferences`。
- 手机号变更要求 `phone_verification_code`；企业邮箱变更暂不直接生效，返回 `EMAIL_VERIFICATION_REQUIRED`，等待邮箱验证接口接入。
- 每次成功保存写入 `audit_logs`，仅记录字段名，不记录生日、手机号和简介原文。

## 当前前端行为

前端已接入真实认证和个人资料接口：进入工作台后读取 `GET /me/profile`，保存时调用 `PATCH /me/profile`，仅在服务端成功后同步表单与侧栏。未包含在 `editable_fields` 中的字段显示为只读；手机号变化时显示短信验证码输入区域。

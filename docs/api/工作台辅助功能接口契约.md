# DevMind AI 工作台辅助功能接口契约

本文件定义“检索测试、历史记录、我的收藏、系统设置”四个功能页的数据与接口，并记录当前前后端已完成的联调契约。

基础地址：`http://localhost:15200/api/v1`。请求携带 `Authorization: Bearer <access_token>`；统一响应：

```json
{ "request_id": "req_xxx", "data": {}, "error": null }
```

列表接口统一返回 `{ "items": [], "next_cursor": null }`，支持 `cursor`、`limit` 分页。

## 1. 检索测试

### 页面期望数据

用户提交测试问题后，需要看到：原始问题、查询改写、召回数量、重排数量、耗时，以及每个候选片段的来源、定位、阶段、排名、相关度和摘要。

### 接口

`POST /retrieval/test`

```json
{
  "query": "生产环境如何配置统一身份认证？",
  "knowledge_base_ids": ["kb_security"],
  "top_k": 20,
  "rerank_top_n": 5
}
```

```json
{
  "request_id": "req_retrieval_01",
  "data": {
    "retrieval_run_id": "run_01",
    "query": "生产环境如何配置统一身份认证？",
    "rewritten_query": "生产环境统一身份认证、OIDC、企业 IdP 配置规范",
    "retrieved_count": 20,
    "reranked_count": 5,
    "latency_ms": 286,
    "results": [
      {
        "chunk_id": "chunk_42",
        "document_id": "doc_auth",
        "document_name": "身份认证接入规范.pdf",
        "location_label": "第 18 页",
        "stage": "rerank",
        "rank": 1,
        "score": 0.94,
        "excerpt": "OIDC 接入应统一使用企业 IdP，并结合 MFA 与角色映射。"
      }
    ]
  },
  "error": null
}
```

后端实现：先对当前用户可访问的知识库过滤，再向 Milvus 召回 `top_k` 个 chunk，调用 reranker 取前 `rerank_top_n`，将本次运行写入 `retrieval_runs`、`retrieval_results`。此接口不调用 LLM、不创建聊天消息。

## 2. 历史记录

### 会话列表

`GET /sessions?cursor=&limit=20&keyword=`

每个会话返回：

```json
{
  "id": "sess_01",
  "title": "统一身份认证接入方案",
  "preview": "生产环境如何配置统一身份认证？",
  "message_count": 6,
  "knowledge_base_ids": ["kb_security"],
  "last_message_at": "2026-08-23T10:00:00Z",
  "created_at": "2026-08-23T09:40:00Z"
}
```

列表按 `last_message_at desc` 排序，只返回当前用户自己的会话。`preview` 取最近一条用户问题的前 120 个字符。

### 查看问题与对应答案

`GET /sessions/{session_id}`

```json
{
  "request_id": "req_session_01",
  "data": {
    "id": "sess_01",
    "title": "统一身份认证接入方案",
    "knowledge_base_ids": ["kb_security"],
    "messages": [
      {
        "id": "msg_u_01",
        "role": "user",
        "content": "生产环境如何配置统一身份认证？",
        "created_at": "2026-08-23T09:41:00Z"
      },
      {
        "id": "msg_a_01",
        "role": "assistant",
        "parent_message_id": "msg_u_01",
        "content": "建议采用 OIDC 与企业 IdP 集成，并启用 MFA…",
        "status": "completed",
        "confidence": "high",
        "citation_count": 3,
        "created_at": "2026-08-23T09:41:03Z",
        "completed_at": "2026-08-23T09:41:07Z"
      }
    ]
  },
  "error": null
}
```

关键要求：每个 AI 回答必须通过 `parent_message_id` 指向其对应的用户问题。前端按时间升序渲染，并用该字段处理追问分支；不要只返回纯文本拼接后的会话摘要。

### 会话操作

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| PATCH | `/sessions/{session_id}` | 修改标题 |
| DELETE | `/sessions/{session_id}` | 软删除当前用户会话 |

`DELETE` 只更新 `deleted_at`，不立刻删除消息、引用和审计数据。无归属的会话返回 `404 SESSION_NOT_FOUND`。

## 3. 我的收藏

### 列表

`GET /favorites?cursor=&limit=20&keyword=`

```json
{
  "request_id": "req_favorite_01",
  "data": {
    "items": [
      {
        "message_id": "msg_a_01",
        "content": "建议采用 OIDC 与企业 IdP 集成，并启用 MFA…",
        "session_id": "sess_01",
        "session_title": "统一身份认证接入方案",
        "question": "生产环境如何配置统一身份认证？",
        "favorited_at": "2026-08-23T10:00:00Z",
        "citation_count": 3,
        "confidence": "high"
      }
    ],
    "next_cursor": null
  },
  "error": null
}
```

收藏列表必须包含 `question` 和 `session_id`，使用户能理解答案上下文并跳回完整会话。

### 操作

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| PUT | `/favorites/messages/{message_id}` | 收藏回答，幂等 |
| DELETE | `/favorites/messages/{message_id}` | 取消收藏，幂等 |

只能收藏当前用户可访问的 `assistant` 消息。取消收藏不删除原会话内容。前端可乐观更新，失败时回滚。

## 4. 系统设置

系统设置只管理当前用户的工作台偏好，不包含组织级安全策略或 SSO 配置。

### 读取设置

`GET /me/preferences`

```json
{
  "request_id": "req_pref_01",
  "data": {
    "default_knowledge_base_ids": ["kb_platform", "kb_security"],
    "default_mode": "tech",
    "locale": "zh-CN",
    "timezone": "Asia/Shanghai",
    "answer_style": "concise"
  },
  "error": null
}
```

### 保存设置

`PATCH /me/preferences`

```json
{
  "default_knowledge_base_ids": ["kb_platform"],
  "default_mode": "tech",
  "locale": "zh-CN",
  "timezone": "Asia/Shanghai",
  "answer_style": "concise"
}
```

字段约束：

| 字段 | 允许值 / 规则 |
| --- | --- |
| `default_knowledge_base_ids` | 仅可保存当前用户有权限的知识库 ID |
| `default_mode` | `tech`、`troubleshoot`、`summarize` |
| `locale` | 如 `zh-CN`、`en-US` |
| `timezone` | IANA 时区，如 `Asia/Shanghai` |
| `answer_style` | `concise`、`balanced`、`detailed` |

后端以 `user_id` 为主键对 `user_preferences` 做 upsert。禁止由前端提交 `user_id`、角色、访问令牌或组织安全设置。

## 5. 权限、审计与错误

1. 所有接口从 Access Token 取得 `user_id` 与 `organization_id`；不能信任请求体的资源归属字段。
2. 历史记录仅返回本人会话；收藏仅返回本人收藏；默认知识库必须再次检查成员权限。
3. 检索测试、会话删除、收藏变更和偏好变更均写入 `audit_logs`。
4. 无权访问时返回 `404`，防止泄露资源存在性；参数错误返回 `400`，状态冲突返回 `409`。

## 6. 当前实现范围

- 检索测试已由正式后端实现，并已接入前端真实查询、Top K、重排数量、耗时与结果展示。
- 历史记录已由正式后端实现，支持关键字搜索、cursor 分页、重命名、软删除，并可恢复完整问题、回答与引用。
- 单条引用详情已实现，用户点击引用卡即可查看有权限的原始分块。
- 收藏已使用 `message_favorites` 持久化，问答页、收藏列表和取消收藏状态保持一致。
- `/me/preferences` 已使用 `user_preferences` 持久化；前端可设置默认知识库、默认回答模式、回答详略、语言和时区，新会话会应用默认知识范围。
- 会话、收藏和偏好变更均执行用户归属或知识库访问权限校验，并写入审计日志。

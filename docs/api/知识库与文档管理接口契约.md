# DevMind AI 知识库与文档管理接口契约

本文供后端实现“知识库”和“文档管理”两个功能页。基础地址为 `http://localhost:15200/api/v1`，请求必须携带 `Authorization: Bearer <access_token>`。

所有成功响应：

```json
{ "request_id": "req_xxx", "data": {}, "error": null }
```

知识库列表使用 cursor 分页：`?cursor=&limit=20`；文档列表使用 `?page=1&page_size=20`，返回 `{ "total": 0, "items": [] }`。

数据库字段与关系见：[工作台数据库设计.md](../database/工作台数据库设计.md)。

## 1. 前端需要展示的数据

### 知识库页

每个知识库至少返回：

```json
{
  "id": "kb_platform",
  "name": "平台工程知识库",
  "description": "平台架构、部署和运行规范",
  "status": "ready",
  "document_count": 128,
  "chunk_count": 3462,
  "member_count": 12,
  "role": "admin",
  "updated_at": "2026-08-23T10:00:00Z",
  "created_at": "2026-08-01T10:00:00Z"
}
```

`status`：`ready`、`indexing`、`failed`、`archived`。`role`：`viewer`、`editor`、`admin`。

### 文档管理页

每条文档至少返回：

```json
{
  "id": "doc_auth",
  "knowledge_base_id": "kb_security",
  "knowledge_base_name": "安全与合规知识库",
  "name": "身份认证接入规范.pdf",
  "source_type": "pdf",
  "mime_type": "application/pdf",
  "size_bytes": 1240000,
  "status": "ready",
  "chunk_count": 42,
  "created_at": "2026-08-22T10:00:00Z",
  "updated_at": "2026-08-23T09:30:00Z",
  "indexed_at": "2026-08-23T09:32:00Z",
  "error_code": null,
  "error_message": null
}
```

`source_type`：`pdf`、`md`、`docx`、`wiki`、`git`、`url`。`status`：`uploaded`、`parsing`、`chunking`、`embedding`、`indexing`、`ready`、`failed`、`deleted`。

## 2. 知识库接口

| 方法 | 路径 | 权限 | 用途 |
| --- | --- | --- | --- |
| GET | `/knowledge-bases` | viewer+ | 列表、搜索、状态筛选 |
| POST | `/knowledge-bases` | 已登录组织成员 | 创建知识库，创建者自动成为 admin |
| GET | `/knowledge-bases/{id}` | member | 详情和统计 |
| PATCH | `/knowledge-bases/{id}` | admin | 修改名称、描述、状态 |
| DELETE | `/knowledge-bases/{id}` | admin | 归档知识库 |
| GET | `/knowledge-bases/{id}/members` | admin | 成员列表 |
| PUT | `/knowledge-bases/{id}/members/{user_id}` | admin | 设置成员角色 |
| DELETE | `/knowledge-bases/{id}/members/{user_id}` | admin | 移除成员 |

添加成员前，前端通过 `GET /organization/users?keyword=张&limit=20` 搜索当前组织用户。接口至少返回 `id`、`username`、`display_name`、`department_name`、`job_title`；禁止返回密码摘要、验证码或令牌。服务端必须固定使用令牌中的 `organization_id`，不接受前端指定组织。

### 列表

`GET /knowledge-bases?keyword=平台&status=ready&cursor=&limit=20`

服务端必须按当前用户的成员关系过滤，只返回其可访问的知识库；不能因为前端传入 ID 而绕过权限。

### 创建与更新

`POST /knowledge-bases`

```json
{ "name": "平台工程知识库", "description": "平台架构、部署和运行规范" }
```

创建者自动成为 `admin`。`PATCH` 只允许更新 `name`、`description`、`status`，名称在同一组织内唯一。

成员角色写入 `knowledge_base_members`：`viewer` 可查看知识库和文档，`editor` 在此基础上可管理文档，`admin` 还可修改/归档知识库并管理成员。无成员关系或跨组织访问统一返回 `404 KNOWLEDGE_BASE_NOT_FOUND`，避免泄露资源是否存在。管理员不能降级或移除知识库中的最后一名管理员，否则返回 `409 LAST_ADMIN_REQUIRED`。

成员设置请求：

```json
{ "role": "viewer" }
```

成员列表响应：

```json
{
  "items": [
    {
      "user_id": "9cfe39e4-1418-4d2f-85a9-a9c84bc93cff",
      "username": "zhang",
      "display_name": "张工程师",
      "department_name": "平台研发部",
      "job_title": "高级后端工程师",
      "role": "admin",
      "created_at": "2026-08-27T10:00:00Z"
    }
  ]
}
```

### 删除

`DELETE /knowledge-bases/{id}` 不立即物理删除，更新为 `archived`，并异步删除其文档对象和 Milvus 向量。若仍有正在执行的文档任务，返回 `409 KNOWLEDGE_BASE_BUSY`。

## 3. 文档接口

| 方法 | 路径 | 权限 | 用途 |
| --- | --- | --- | --- |
| GET | `/documents` | viewer+ | 跨知识库文档列表 |
| POST | `/documents` | editor+ | 上传文件并创建解析任务 |
| GET | `/documents/{id}` | member | 文档详情、处理状态 |
| PATCH | `/documents/{id}` | editor+ | 修改名称或元数据 |
| DELETE | `/documents/{id}` | editor+ | 软删除文档 |
| POST | `/documents/{id}/reindex` | editor+ | 重新解析、分块、向量化 |
| GET | `/documents/{id}/chunks` | editor+ | 分块预览和定位 |
| GET | `/documents/{id}/task` | viewer+ | 最近一次处理任务及进度 |

### 文档列表

`GET /documents?page=1&page_size=20&keyword=认证&source_type=pdf`

筛选参数均可选。返回的每条记录必须携带 `knowledge_base_name`，避免前端为表格逐条补请求。

### 上传

`POST /documents`，使用 `multipart/form-data`：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `file` | 是 | PDF、Markdown、DOCX 等文件 |
| `knowledge_base_id` | 是 | 目标知识库 |
| `display_name` | 否 | 前端显示名，默认文件名 |
| `metadata` | 否 | JSON 字符串，如标签、来源 URL |

成功响应为 `202 Accepted`：

```json
{
  "request_id": "req_upload_01",
  "data": { "id": "doc_auth", "status": "uploaded", "task_id": "task_01" },
  "error": null
}
```

前端随后轮询 `GET /documents/{id}`，或通过任务事件订阅状态变化；不要在上传请求中同步等待解析完成。

当前实现可轮询 `GET /documents/{id}/task`：

```json
{
  "task_id": "c2913437-a6c6-43ef-b54a-4692bf16b459",
  "task_type": "ingest",
  "status": "running",
  "progress": 70,
  "attempt_count": 1,
  "max_attempts": 3,
  "available_at": "2026-08-27T11:30:00Z",
  "heartbeat_at": "2026-08-27T11:31:00Z",
  "error_code": null,
  "error_message": null,
  "started_at": "2026-08-27T11:30:00Z",
  "completed_at": null
}
```

`task_type` 为 `ingest/reindex/delete`，`status` 为 `pending/running/retry_wait/completed/failed/dead`。Worker 处理阶段依次更新文档状态 `uploaded → parsing → chunking → embedding → ready`；执行失败后按指数退避进入 `retry_wait`，耗尽次数后进入 `dead`。

### 失败任务人工重试

`POST /documents/{id}/task/retry`

仅编辑者或管理员可以重试最新的 `failed/dead` 任务。成功返回 `202`，原任务会重置为 `pending` 并由独立 Worker 重新领取；存在活动任务时返回 `409 DOCUMENT_PROCESSING`。

### 重建索引

`POST /documents/{id}/reindex`

```json
{ "force": false }
```

成功返回 `202` 和新的 `task_id`。当已有解析任务运行时返回 `409 DOCUMENT_PROCESSING`；`force=true` 只允许管理员使用。

### 分块预览

`GET /documents/{id}/chunks?cursor=&limit=50`

返回：

```json
{
  "items": [
    {
      "id": "chunk_42",
      "chunk_no": 42,
      "location_label": "第 18 页",
      "content": "OIDC 接入应统一使用企业 IdP…",
      "token_count": 238,
      "indexed": true
    }
  ],
  "next_cursor": null
}
```

## 4. 后端处理流程

```text
上传文件
  → 校验文件签名、压缩结构、活动内容并执行 ClamAV 扫描
  → 扫描通过后写入对象存储，documents.status=uploaded
  → 创建异步任务，status=parsing
  → 文本提取
  → 分块，写入 document_chunks
  → Embedding 写入 Milvus，回填 milvus_pk
  → status=ready，更新 document_count / chunk_count
```

失败时将 `documents.status` 设为 `failed`，并写入稳定的 `error_code` 与可展示的 `error_message`。推荐错误码：

| 错误码 | 含义 | 前端动作 |
| --- | --- | --- |
| `UNSUPPORTED_FILE_TYPE` | 文件类型不支持 | 提示允许的类型 |
| `FILE_TOO_LARGE` | 超出大小限制 | 提示拆分或联系管理员 |
| `DUPLICATE_DOCUMENT` | 相同 checksum 已存在 | 提供查看或覆盖入口 |
| `DOCUMENT_PROCESSING` | 正在解析或索引 | 禁止重复提交 |
| `DOCUMENT_PARSE_FAILED` | 文本提取失败 | 显示失败原因与重试按钮 |
| `KNOWLEDGE_BASE_ACCESS_DENIED` | 没有知识库权限 | 不展示资源详情 |
| `FILE_TYPE_MISMATCH` | 扩展名与 MIME 不一致 | 要求重新选择正确文件 |
| `INVALID_PDF` / `INVALID_DOCX` | 文件签名或结构无效 | 拒绝上传 |
| `ARCHIVE_BOMB` | DOCX 文件数、解压大小或压缩比异常 | 拒绝上传并联系管理员 |
| `ACTIVE_DOCUMENT_CONTENT` | 包含脚本、宏或嵌入对象 | 拒绝上传 |
| `MALWARE_DETECTED` | ClamAV 检出恶意文件 | 拒绝上传并提示安全风险 |
| `FILE_SCANNER_UNAVAILABLE` | 生产扫描服务不可用 | 失败关闭，不保存文件 |

## 5. 实现约束

1. 所有查询同时按 `organization_id` 和成员角色过滤；无权限资源返回 `404`，不泄露是否存在。
2. 文件内容放对象存储，`documents.storage_key` 只保存引用；不要把文件二进制写入 PostgreSQL。
3. 以 `checksum + knowledge_base_id` 去重。重复文件默认返回 `409 DUPLICATE_DOCUMENT`，不产生第二份向量。
4. 解析、向量化与删除必须异步执行；接口只负责创建任务并返回状态。
5. 文档状态变更、下载、删除、重建索引都写入 `audit_logs`。
6. 物理删除前，先软删除数据库记录，再清理对象存储和 Milvus，保证重试幂等。

## 6. 当前代码与生产实现差异

知识库 CRUD、成员权限、文档上传/编辑/软删除/重新索引/分块预览、MinIO 对象存储、PostgreSQL 任务状态、BGE-M3 向量化和 Milvus 写入均已接入正式接口。`backend/app/api/workspace.py` 仅保留为前端 Mock 参考，不注册到正式服务。

上传文件在写入 MinIO 前必须通过扩展名/MIME 一致性、真实文件签名、UTF-8 文本、DOCX 压缩包安全和活动内容检查。生产环境强制启用 ClamAV；扫描服务不可用时失败关闭。当前文档任务已由 `python -m backend.app.worker` 独立执行。Worker 使用 PostgreSQL 租约和 `FOR UPDATE SKIP LOCKED` 安全领取任务，支持多 Worker、心跳恢复、超时、指数退避和死信；FastAPI 只负责创建任务并立即返回。

前端已接入本文件中的正式接口：知识库新建、编辑、状态筛选、成员搜索/添加/改权/移除与归档，以及文档目标知识库选择、类型筛选、上传、任务自动轮询、人工重试、重命名、分块预览、重索引和删除，均不再使用 Mock 数据。任务处于 `pending/running/retry_wait` 时每 1.5 秒轮询一次，进入 `completed/failed/dead` 后自动停止。
# 权限边界

接口返回数据和允许动作由“组织 + 知识库角色 + 内容密级/部门”共同决定：

| 能力 | viewer | editor | admin |
| --- | --- | --- | --- |
| 查看知识库与允许访问的文档 | 是 | 是 | 是 |
| 上传、修改、删除、重试、普通重建索引 | 否 | 是 | 是 |
| 强制替换待执行索引任务 | 否 | 否 | 是 |
| 修改/归档知识库、查看及管理成员 | 否 | 否 | 是 |

读取文档时还需满足：文档密级不高于用户密级；非 `public` 文档的 `team` 有值时必须与用户部门一致。无权访问与跨组织资源统一返回 `404`，角色不足返回 `403 KNOWLEDGE_BASE_ROLE_REQUIRED`。前端隐藏按钮只用于交互提示，后端对每次请求独立执行上述校验。

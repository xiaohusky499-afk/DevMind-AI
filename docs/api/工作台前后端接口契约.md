## 当前实现状态

正式 PostgreSQL/Milvus 接口已经实现会话、消息、权限过滤混合检索、BGE 重排序、WebSocket 流式回答、引用、可信度、检索测试和文档完整入库链路。`backend/app/api/workspace.py` 仅保留为不注册的 Mock 参考。

前端智能问答页已经接入上述正式接口：支持首次自动创建会话、上下文连续追问、事件驱动进度、增量 Token、引用侧栏、异常提示和历史会话恢复。开发环境必须同时代理 `/api` 的 HTTP 与 WebSocket 请求。

收藏、回答反馈和个人偏好仍按本文契约继续实现。登录、注册、短信验证码和退出登录的完整约定见：[登录页接口契约.md](登录页接口契约.md)。

## 2. 会话与消息

### 创建会话

`POST /api/v1/sessions`

```json
{ "title": "", "knowledge_base_ids": ["kb_platform", "kb_security"] }
```

```json
{ "request_id": "req_01", "data": { "id": "sess_01", "title": "新建对话", "updated_at": "2026-08-22T13:00:00Z" }, "error": null }
```

### 会话列表和详情

- `GET /api/v1/sessions?cursor=&limit=20`
- `GET /api/v1/sessions/{session_id}`

详情中的 `messages` 需要按时间升序返回。每条 AI 消息必须包含 `id`、`content`、`status`、`citation_count`、`confidence`；不用内嵌完整引用内容，避免历史列表过大。

### 创建用户消息

`POST /api/v1/messages`

```json
{
  "session_id": "sess_01",
  "content": "生产环境如何配置统一身份认证？",
  "mode": "tech",
  "knowledge_base_ids": ["kb_platform", "kb_security"],
  "parent_message_id": null
}
```

```json
{
  "request_id": "req_02",
  "data": {
    "user_message_id": "msg_u_01",
    "assistant_message_id": "msg_a_01",
    "stream_url": "/api/v1/chat/stream?message_id=msg_a_01&ticket=一次性票据"
  },
  "error": null
}
```

后端在这里创建两条消息记录，避免流式断开后出现无归属的回答。

## 3. 流式问答协议

前端直接连接创建消息接口返回的 `stream_url`。URL 携带有效期 5 分钟、仅可消费一次的 Redis 票据，不携带 JWT，避免访问日志泄露令牌。服务端事件一律为 JSON：

```json
{ "type": "retrieval", "data": { "stage": "search", "message": "正在检索 12 个知识库…", "retrieved_count": 13 } }
```

| `type` | `data` | 前端动作 |
| --- | --- | --- |
| `status` | `{ "stage": "analyzing", "message": "正在分析问题…" }` | 显示思考状态 |
| `retrieval` | `{ "stage": "search|recall|rerank", "message": "…", "retrieved_count": 13, "reranked_count": 5 }` | 点亮 RAG 进度节点 |
| `token` | `{ "content": "增量文本" }` | 追加到 AI 回答卡 |
| `citations` | `{ "items": [Citation] }` | 右侧卡片依次出现 |
| `final` | `{ "message_id": "msg_a_01", "confidence": "high", "citation_count": 5, "usage": { "input_tokens": 0, "output_tokens": 0 } }` | 停止流式、显示操作按钮 |
| `error` | `{ "code": "RAG_FAILED", "message": "检索失败，可重试" }` | 保留用户问题并展示重试按钮 |

断线后前端用 `GET /api/v1/messages/{message_id}` 取已落库内容；一次性票据不能重放，也不要重新提交同一个问题。

## 4. 引用与可信度

### 引用列表

`GET /api/v1/messages/{message_id}/citations`

```json
{
  "request_id": "req_03",
  "data": {
    "answer_basis_count": 5,
    "confidence": "high",
    "items": [
      {
        "id": "cite_01",
        "document_id": "doc_01",
        "document_name": "身份认证接入规范.pdf",
        "document_type": "pdf",
        "location_label": "第 18 页",
        "chunk_id": "chunk_42",
        "score": 0.94,
        "excerpt": "OIDC 接入应统一使用企业 IdP，并结合 MFA 与角色…",
        "url": null
      }
    ]
  },
  "error": null
}
```

`score` 固定为 0 到 1 的数值，前端格式化为百分比；`confidence` 仅允许 `high`、`medium`、`low`。

### 引用详情

`GET /api/v1/citations/{citation_id}` 返回 `document_id`、`location_label`、`excerpt`、`content`、`highlights`、`access_allowed`。无权限返回 `403 DOCUMENT_ACCESS_DENIED`，前端不能展示片段正文。

## 5. 收藏、反馈与个人配置

### 收藏

- `PUT /api/v1/favorites/messages/{message_id}`
- `DELETE /api/v1/favorites/messages/{message_id}`
- `GET /api/v1/favorites?cursor=&limit=20`

收藏接口返回 `{ "message_id": "msg_a_01", "favorited": true }`；按钮可乐观更新，失败时回滚。

### 回答反馈

`POST /api/v1/messages/{message_id}/feedback`

```json
{ "rating": "up", "reason": "", "comment": "" }
```

`rating` 只允许 `up`、`down`、`handoff`。`handoff` 时可额外返回工单 ID。

### 用户与偏好

- `GET /api/v1/me`
- `GET /api/v1/me/preferences`
- `PATCH /api/v1/me/preferences`

偏好字段建议仅保留 `default_knowledge_base_ids`、`default_mode`、`locale`，不在前端存储访问令牌。

## 6. 知识库、文档和检索测试

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/knowledge-bases` | Sidebar / 选择知识库时的可访问知识库列表，返回 `id`、`name`、`document_count`、`status` |
| `GET /api/v1/documents?knowledge_base_id=&cursor=` | 文档管理列表 |
| `POST /api/v1/documents` | 上传文档，使用 `multipart/form-data` |
| `POST /api/v1/retrieval/test` | 返回 Query 改写、召回片段、重排分数，不生成答案 |

检索测试请求：

```json
{ "query": "统一身份认证", "knowledge_base_ids": ["kb_security"], "top_k": 20, "rerank_top_n": 5 }
```

## 7. 后端实现约束

1. 每个接口都由鉴权层根据用户身份过滤会话、知识库、文档和引用，不信任前端传入的 `knowledge_base_ids`。
2. `session_id`、`message_id` 和 `citation_id` 使用不可枚举 ID；未归属资源返回 404，不泄露存在性。
3. 流式生成按 token 或 20 到 80 个字符小块推送。状态事件的顺序必须是 `analyzing → search → recall → rerank → generating → final`。
4. RAG 检索和生成应写入审计日志：用户、会话、知识库、文档、查询摘要、时间、耗时和结果状态；不要记录原始令牌或敏感正文。
5. 第一阶段无需引入任务队列或复杂工具调用。长文档解析与大文件上传达到容量瓶颈后，再异步化。
